## Stack

**TanStack Start** (React 19 + TypeScript, server-side rendering, file-based routing) on **Vite**, Tailwind CSS 4, shadcn/ui components, `lucide-react` icons, `recharts` for the Appendix charts, `vitest` for tests. The Vite/TanStack/Nitro setup comes from `@lovable.dev/vite-tanstack-config` (see the comments in `vite.config.ts` before changing it).

## Where things are

| Path | What it does |
|---|---|
| `src/routes/` | One file per page: `index.tsx` (Stage), `person.tsx`, `counter.tsx`, `contact.tsx`, `bank.tsx`, `appendix.tsx`; `__root.tsx` is the app shell. File-based routing: see `src/routes/README.md`. `routeTree.gen.ts` is generated — do not edit it. |
| `src/components/sentinel/` | The demo's components: `TopBar` (navigation, scenario selector, demo controls, Live/Offline chip), `PhoneFrame`, `ContactPhone`, `CounterConsole`, `StatusPill`, `Timeline`, … |
| `src/lib/api.ts` | API types and client — field names match `docs/api.md`, do not rename them. 3-second timeout, then the offline fallback. |
| `src/state/DemoContext.tsx` | Demo state: consent, trusted contact, approve/block decisions, simulated clocks (30 minutes, 72 hours), pending revocation. |
| `src/lib/format.ts` | Amounts (`CHF 40,000`), scores, percentages. |
| `public/demo-fallback.json` | Offline data: same shapes as `GET /demo-bundle`. **Generated by the back-end**, do not edit by hand. |
| `src/**/*.test.ts(x)` | Tests (API client and fallback logic, case state, routing). |

## Run it locally

```bash
cd frontend
npm install
echo "VITE_API_URL=https://sentinel-production-4a83eb72.up.railway.app" > .env.local   # or http://localhost:8000
npm run dev          # http://localhost:8080 in Codespaces with:  npm run dev -- --host 0.0.0.0 --port 8080
npm test             # vitest
npm run build        # what Vercel runs
```

Without `VITE_API_URL` the app runs entirely on `public/demo-fallback.json`. `.env.local` is git-ignored: never commit it.

The folder contains `bun.lock` (from Lovable); the group has been using **npm** (`npm install --no-package-lock`). Pick one package manager before the code freeze so that local builds and Vercel install the same versions.

## Deploy (Vercel)

Already configured — only for reference if the project is recreated:

- Import `Amg-challenge/SENTINEL` → **Root Directory:** `frontend` → **Production Branch:** `main`.
- **Application Preset:** Vite (Vercel first suggested "TanStack Start" and shows a "Possible configuration mismatch" warning). Checked on 16 November: every page works, also when opened directly, so the setting is kept as is.
- **Environment Variable:** `VITE_API_URL` = the Railway URL (no trailing slash), for Production and Preview. Vite reads it at build time: after changing it, redeploy.
- Every merge into `main` redeploys automatically.

## Rules

- API base URL only from `import.meta.env.VITE_API_URL`.
- If the API does not answer within 3 seconds, use `public/demo-fallback.json`: the demo must never stop on stage.
- Demo state lives in the front-end; the API is stateless. Reloading the page resets the demo (by design for now).
- After changing the engine, the scenarios or the threshold, regenerate the fallback from `backend/`: `python scripts/export_demo_data.py`.
- The money protected is a benefit for the client and the family: never present it as the reason the bank pays (document v6).
- Changes go through a Pull Request to `main` from the `interfaccia` branch; check `npm run build` and `npm test` first.

## Known limitations

- Reloading the page resets consent, decisions and clocks (no persistence yet; optional).
